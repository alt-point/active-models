# Инварианты, транзакции, diff и undo

Четыре инструмента целостности **во времени и между полями**; в основе у всех одна идея: то, что было валидным, всегда
можно вернуть.

## Инварианты: правила о нескольких полях

Правило о двух полях (`end >= start`) не может выполняться между двумя записями, которые его выполняют, поэтому на
каждую запись оно не проверяется. Его проверяют `validate()`, `assertValid()`, `create(data, { validate: true })`,
`transaction()` и атомарный `fill()`.

```ts
class Trip extends ActiveModel {
  @ActiveField({ coerce: 'date' }) start?: Date
  @ActiveField({ coerce: 'date' }) end?: Date

  @InvariantMethod('end must not be before start')
  static endAfterStart (trip: Trip) {
    return !trip.start || !trip.end || trip.end >= trip.start   // false (или строка-сообщение) = нарушено
  }
}

// без декоратора:
Trip.defineInvariant('end after start', (t) => t.end >= t.start ? true : `end ${t.end} is before ${t.start}`)
```

Нарушение приходит как `{ path: '', code: 'invariant', message }` (для вложенной модели `path` — поле, в котором она
лежит: `trip`, `legs[1]`). Проверка, которая бросает исключение, считается нарушенной. Инварианты наследуются подклассами.

## `transaction()`: всё или ничего

```ts
trip.transaction((t) => {
  t.seats = 9
  t.start = new Date('2026-05-20')
  t.end = new Date('2026-05-05')      // модель теперь невалидна...
})                                    // ...значит всё откатится и будет брошен ValidationError
```

Если `fn` бросила исключение или к концу модель невалидна (правило, validator или инвариант), **каждое поле
возвращается** и ошибка пробрасывается: ни один вызывающий код не увидит полуизменённую модель. Возвращает то, что вернула
`fn`; `async`-функция ожидается. Транзакции вкладываются, каждая откатывается к своему началу.

`fill(data, { atomic: true })` — транзакция вокруг `fill()`; обычный `fill` оставляет всё, что записал до первого
отклонённого значения.

- События эмитятся по ходу записей и не «отзываются»; откат эмитит свои события для полей, которые возвращает.
- Вложенные модели и коллекции восстанавливаются **свежими копиями**, поэтому сохранённая вами ссылка на старый
  вложенный экземпляр устареет.
- Откат обходит правила и переходы (эти значения были валидны, когда их взяли).

## Diff и revert

```ts
const profile = Profile.create(data, { tracked: true })
profile.name = 'x'
profile.trips.push({ seats: 9 })

profile.changes()        // { name: { from: 'n', to: 'x' }, trips: { from: <копия>, to: <коллекция> } }
profile.dirtyFields()    // ['name', 'trips']
profile.isDirty('name')  // true

profile.revert('name')   // одно поле назад
profile.reset()          // всё назад (revert() без аргумента)
```

Если `isTouched()` отвечает, **менялось ли** что-то, то `changes()` — **что именно**. Вложенные модели и списки
сравниваются по содержимому, `from` — копия, а в отличие от `isTouched()` в diff попадают и `hidden`-поля. Откат
восстанавливает свежие живые копии вложенных моделей и коллекций, обходит правила и эмитит обычные события. Нужна модель
с `{ tracked: true }` (она хранит нетронутую копию, снятую сразу после создания; `clone()` делит её с оригиналом).

## Undo и redo

```ts
const note = Note.create({ text: 'a' }, { history: true })     // или { history: { limit: 50 } }
note.text = 'b'
note.text = 'c'
note.undo()      // text === 'b'
note.undo()      // text === 'a'
note.redo()      // text === 'b'
note.canUndo(), note.canRedo(), note.clearHistory()
```

Каждая запись после создания — шаг (по умолчанию хранится 100). Новая запись очищает шаги redo; целая `transaction()` или
атомарный `fill()` — **один** шаг, а откатившаяся не оставляет ни одного. Undo/redo обходят правила и переходы и сами не
записываются.

## Ограничения

- **Изменение «на месте»** (`arr.push()`, обычный вложенный объект) не видно ни истории, ни undo — они видят присваивания
  полей. Вложенные `ActiveModel` и `ActiveCollection` `changes()` сравнивает по содержимому, но их собственные правки не
  становятся шагами undo родителя.
- `changes()`/`revert()` держат вторую копию модели: tracked-модель стоит примерно вдвое больше памяти.
- Это методы прототипа (`validate`, `transaction`, `changes`, `revert`, `reset`, `undo`, `redo`, ...): не называйте так поля.
